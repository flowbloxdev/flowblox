Explaining Project Space:

1) Purpose and discovery
- Project Space stores public and private FlowBlox projects that can be reused through ExecuteProjectFlowBlock.
- Before building complex logic, search for an existing solution. For example, IMAP provider discovery requires Thunderbird API
  requests, XML selection and username substitution; a shared mail-settings flow can supply these settings from an email address.
  Never invent GUIDs or input/output names.
- Respect the user's preference for shared subflows or local implementation; ask before adding a shared dependency if that preference is unclear.
- GetPSProjects(searchForNames=..., visibility=public|private|all) searches names and descriptions with case-insensitive contains-OR
  matching. Empty terms list all matches. Results include descriptions, projectSpaceGuid, stableVersions and projectSpaceVersion.
  Discovery reads metadata only; it does not download project content.

2) Inspect and reuse
- GetSkillProject(projectSpaceGuid=..., projectSpaceVersion=..., private=...) loads a selected definition without executing startup
  commands. It returns input types, defaults, required/password flags, allowed values and outputs. Input defaultValue applies when
  the input is omitted or empty. Keep field references as placeholders; let runtime components resolve them.
- Prefer the latest stable version: its content is immutable. Discovery returns its number as projectSpaceVersion.
  Inspection and execution select the latest stable version when omitted; if none exists, they use current project content.
  Pass the selected version explicitly when executing or wiring a dependency so later releases do not silently change it.
- ExecuteExternalProject accepts projectSpaceGuid and optional projectSpaceVersion instead of projectFile, plus reason,
  inputParameters and optional outputFields. The normal execution confirmation applies; PS approvals are per invocation.
- To reuse the project in a flow, configure ExecuteProjectFlowBlock.ProjectSpaceGuid and optional ProjectSpaceVersion,
  map its inputs, and use ProjectOutputIteratorFlowBlock for its named outputs. Set AbortOnError=true and AbortOnWarning=false.
  ProjectSpaceVersion requires a GUID. Clear ProjectFile when using a PS reference; local paths may fail on other machines.

3) Authentication
- Public search and downloads require no account. Private search uses the current login or restores remembered credentials
  through FlowBlox's account manager. Set private=true for private inspection/execution.
- On missing authentication, ask the user to sign in at the configured endpoint with Remember credentials enabled.
  Never request passwords or tokens in tool arguments. Remember credentials is required by the isolated execution process.
- Uploading, updating, managing own projects and stable versions require login. Registration opens from Project Space;
  the user must confirm the registration email before signing in.

4) User interface and publishing
- Open View projects (Project-Space) to search, open projects or stable versions. My Projects requires login.
- Save to Project Space uploads metadata and content together. Name and Description remain required; Visibility is Private or Public.
  UseProjectDescriptionForProjectSpace defaults to true: the upload description is read-only and follows ProjectDescription.
  Disable it only for a separate PS description. Create new project creates a new GUID; Update existing project keeps its GUID.
- Manage versions / Create stable version creates an immutable snapshot of current content. Version comments/metadata can be
  edited later; version content cannot. Referenced local projects should also be published and bound by PS GUID where appropriate.
