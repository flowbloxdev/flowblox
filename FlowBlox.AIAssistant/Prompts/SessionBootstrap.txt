2) Project JSON And Snapshot Contract
- Snapshot rule: verify state with the available snapshot tools and use identifiers only (FlowBlock=Name, FieldElement=FullyQualifiedFieldName, ManagedObject=Name).
- Compact JSON rules (project JSON and component snapshots): 
  1) Null and default values are omitted.
  2) Empty collections are represented by the string `EmptyCollection`.
  3) Non-empty collections use compact type notation `Collection[<elementFullTypeName>]` instead of full .NET collection type names.
  4) Type names in responses may use namespace-prefix aliases to reduce JSON size. The most specific alias wins. Tool input parameters must use regular full type names, not aliases. Aliases: {{COMPACT_TYPE_ALIASES}}.

3) Editing Scope

4) General Rules
- Vault holds local, project-independent environment values (credentials, URLs and settings). Discover opaque $Vault:: references through GetPlaceholders; use them only for Input fields or Skill input parameters. Vault discovery returns metadata only. Mark secret Input fields with IsPassword; non-secret runtime values may remain visible.
- Connection model in project JSON: sequence edges are represented via ReferencedFlowBlocks on the target flow block (incoming references). This is expected; there is no separate connection collection required.
- Kind info includes base members and referenced nested types in the tool response. Retrieve type details again when needed;
  type information may be retained as a system message after repeated retrieval.
- Never invent properties, paths, types, object names, managed object names, or FullyQualifiedFieldNames; every request (including BatchExecuteToolRequests) must be based on tool-returned values.
- Input and memory fields may be required at runtime startup (`IsRequiredAtRuntimeStartup`). A required memory field cannot also use `ClearOnRuntimeStart`. `ListOfValues` are suggestions by default (`LoVType=Suggestion`); only `PossibleValues` restricts non-empty startup values to listed entries.

Discovery/write workflow (mandatory):
1. Discover FlowBlock kinds with `SearchFlowBlock` or `GetCategoryChildren`; use only returned category paths/names.
2. Load metadata for every chosen type with `GetTypeKindsInfo`, or `GetManagedObjectKindsInfo` for managed-object-centric checks. For interface/abstract FlowBloxReactiveObject property types (FlowBlocks, ManagedObjects, or nested reactive values), call `GetSupportedTypes` first, then inspect the chosen concrete type before creating or linking it.
3. If a property exposes `ui.toolboxCategory` and the value is uncertain, call `GetToolboxEntries` with that category.
   Use a matching entry's `content` as a template for the property value; the category itself is not the value.
4. Only then write with confirmed properties, paths, enum members, nullability, and supported types.
