# OAuth user connections

`OAuthUserConnection` is a provider-neutral managed object for authorization-code flow with PKCE.
Select it under **Authentication > OAuth user connection** in either the WebRequest or OpenAPI REST block.
No Swagger, OpenAPI or Google Discovery import is required for the WebRequest block.

## Running a flow

- On the first authenticated request, FlowBlox opens the system browser and waits for the user's sign-in and consent.
  There is no additional FlowBlox sign-in window. The pending flow can be stopped with the normal execution cancellation.
- Browser authorization times out after three minutes. A declined or cancelled authorization does not send the API request.
- Later requests reuse the local access token or renew it with the refresh token. Refresh-token rotation is saved atomically;
  concurrent requests and processes share a file lock so they do not independently reuse a rotated refresh token.
- Background/runner processes do not open a browser. They can reuse credentials previously authorized by the same Windows user.
  If authorization is needed without an interactive service, the block reports the Error notification **OAuth sign-in required**.
- Optional managed-object actions **Connect account in browser** and **Disconnect local account** allow connection management
  outside a running flow. Disconnect deletes local credentials; it does not revoke consent at the provider.

## Configuration

- Authorization endpoint and token endpoint: the provider's OAuth URLs.
- Client ID: register a native/desktop client with the provider.
- Client secret reference: optional field reference if the provider's desktop client requires `client_secret` in the token
  request. Prefer `$Vault::...`; input parameters and enabled options work through the normal field selection as well.
  For an input parameter, configure `IsPassword` to control its password handling. There is no automatic secret detection.
- Scopes: space-separated API permissions.
- API base URL: credentials are allowed only within this URL's origin and path. For example,
  `https://api.example.com/v1/` permits requests within that API path but not requests to an unrelated host.
- Loopback redirect port: `0` chooses a free port. The redirect is `http://127.0.0.1:<port>/oauth/callback/`.
  Use a fixed registered port if required by the provider.
- Additional authorization parameters: provider-specific values such as `access_type=offline` and `prompt=consent`.
  PKCE, state, client ID, redirect URI and scope parameters are generated by FlowBlox and cannot be overridden here.

Editable connection values support field/option references and are resolved when used. Options must be enabled for placeholder use.
Changing the resolved provider,
client, scopes or API boundary selects a different local credential record and requires fresh authorization.

Access tokens, refresh tokens and the authorized session's resolved client secret are stored in the current Windows user's
protected `%LOCALAPPDATA%\FlowBlox\oauth` storage. Use references rather than literal secrets in the connection configuration,
which is part of the project file. Copying a project to another user/machine does not copy its login.

## Authentication validation

The OAuth association has a `CustomValidation` annotation. An OAuth user connection must not be combined with:

- the REST block's Bearer-token property;
- an `Authorization` header, regardless of header-name casing;
- Basic authentication credentials.

The annotation checks configuration consistency during the standard validation before runtime startup. An unassigned OAuth
connection is valid. Execution does not repeat this property validation. Other headers, such as `Accept` or `Content-Type`, remain usable.
The existing client-credentials/password OAuth block is unchanged.
